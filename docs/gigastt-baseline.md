# GigaSTT Baseline

Дата: 2026-06-25.

## Что проверено

Первый ASR baseline собран на `gigastt 2.5.0` с GigaAM v3 `rnnt` INT8:

- бинарник: `tools/bin/gigastt`;
- модели: `.models/gigastt`;
- пунктуация: `.models/gigastt/punct`;
- тестовый фрагмент: первые 120 секунд `Inbox/Оля коридоре а сайта восторга.m4a`.

Команда:

```bash
.venv/bin/voice-recognizer transcribe-gigastt 'Inbox/Оля коридоре а сайта восторга.m4a' --start 0 --duration 120
```

Результаты:

- длительность аудио: 120 секунд;
- время обработки после загрузки моделей: 5.40 секунды;
- RTF: 0.045;
- слов: 90;
- найденных спикеров: 0.

Файлы результата:

- `outputs/Оля_коридоре_а_саи_та_восторга_0s_120s.gigastt.json`;
- `outputs/Оля_коридоре_а_саи_та_восторга_0s_120s.transcript.md`.

Полный файл `Inbox/Оля коридоре а сайта восторга.m4a`:

- длительность аудио: 27:47;
- время обработки: 47.72 секунды;
- RTF: 0.029;
- слов: 1629;
- найденных спикеров: 0.

## Наблюдения

- ASR быстрый и в целом читабельный для русского разговорного аудио.
- Пунктуация работает, но местами выглядит шумно: например, возможны странные заглавные буквы.
- Word timestamps есть, но первый тест показал как минимум один подозрительный длинный интервал у слова в начале фрагмента.
- Встроенная offline diarization GigaSTT не сработала: `Invalid rank for input: input_features Got: 2 Expected: 3`.
- Это делает GigaSTT хорошим ASR baseline, но не решает нашу основную задачу разделения спикеров.

## Вывод

Оставляем GigaSTT как быстрый локальный ASR-кандидат на GigaAM v3. Для speaker diarization следующим этапом нужен отдельный backend:

- pyannote Community-1 как основной quality-кандидат;
- WhisperX/pyannote как контрольная связка;
- SpeakerKit/Core ML как Apple Silicon-кандидат, если pyannote окажется слишком медленным или неудобным.
