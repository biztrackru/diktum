# Product Requirements

Дата: 2026-06-26.

## Принципы продукта

Voice Recognizer развивается как приватный local-first/self-host сервис для длинных диктофонных записей.

Ключевые требования:

- локальная работа на личном компьютере или на своем сервере;
- приватность по умолчанию: аудио, токены, промежуточные файлы и транскрипты не уходят во внешние сервисы без явного выбора пользователя;
- отсутствие обязательных регулярных платежей;
- поддержка обычных источников записи: iPhone Voice Memos, телефоны, диктофоны, петлички с памятью, `.m4a`, `.mp3`, `.wav`, `.mp4`;
- выбор ASR/AI движка, включая модели, сильные на русском языке;
- пакетная обработка папок и очередей из многих файлов;
- отсутствие практического лимита длины файла за счет чанкинга, возобновления и сохранения промежуточных результатов;
- экспорт в удобные текстовые форматы для дальнейшей работы с AI-агентами и людьми.

## Не цели ближайшего этапа

- публичный GitHub-релиз;
- внешний лендинг;
- SaaS с мультиарендностью и биллингом;
- обязательная native macOS-перепись на SwiftUI;
- зависимость от одного облачного ASR-провайдера.

## Целевая архитектурная форма

Основной продуктовый слой:

```text
Python pipeline + local web UI + file-based storage + optional self-host deployment
```

Оболочки поверх ядра могут появиться позже:

- macOS launcher или Tauri/Simple native wrapper;
- Docker Compose для своего сервера;
- cloud profile для выделенного сервера или приватной VM.

Важно: ASR, diarization, speaker labeling, exports и очередь задач должны жить в общем ядре, чтобы не переписывать логику под каждую оболочку.

## Модель приватности

По умолчанию сервис работает так:

- входные файлы лежат в `Inbox/` или загружаются через локальный UI;
- результаты пишутся в `outputs/`;
- кеш и подготовленные WAV пишутся в `.cache/`;
- модели лежат локально в `.models/` или во внешних локальных папках;
- `.env`, токены, аудио, кеши и результаты не коммитятся.

Если позже добавляются внешние API, каждый такой движок должен быть явно помечен как внешний и требовать отдельного согласия пользователя.

## Движки распознавания

Движки должны быть подключаемыми через единый интерфейс:

- `gigastt-gigaam-v3` как текущий основной русский ASR;
- локальные Whisper варианты;
- возможные интеграции с уже установленными приложениями, если их модели/CLI/API реально доступны;
- будущие серверные профили через ONNX/Triton/другие runtime.

UI должен показывать не только название движка, но и его свойства:

- локальный или внешний;
- поддерживает ли word timestamps;
- поддерживает ли длинные файлы напрямую или только через чанкинг;
- подходит ли для русского языка;
- какие модели/пути требуются.

## Критерии успеха ближайшего этапа

- пользователь может загрузить один или много аудиофайлов через браузер или положить их в `Inbox/`;
- длинный файл больше 2 часов уходит в обработку без ошибки лимита ASR;
- batch job показывает прогресс по файлам и не блокирует интерфейс;
- для каждого файла число спикеров определяется независимо или ограничивается настройками конкретного файла;
- после обработки можно прослушать samples, назначить имена и перегенерировать экспорты без повторного ASR;
- результаты открываются кликом из UI;
- проект имеет первый безопасный локальный git baseline без аудио, токенов и generated artifacts.
