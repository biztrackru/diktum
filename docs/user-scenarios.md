# User Scenarios

Дата: 2026-06-25.

## Лучший путь

Оптимальная логика локального сервиса:

```text
Inbox -> Настройки -> Очередь -> Спикеры -> Экспорт
```

Пользователь не должен думать о внутренних командах, моделях и промежуточных JSON. В интерфейсе должны быть видны только нужные решения:

- какую запись или набор записей обработать;
- полный файл или тестовый фрагмент;
- какой ASR backend и устройство использовать;
- сколько примерно спикеров ожидать;
- где лежат результаты;
- какие имена дать найденным голосам;
- какие файлы открыть после обработки.

## Основные сценарии

### 1. Один файл целиком

1. Положить запись в `Inbox`.
2. Выбрать файл.
3. Оставить `Старт` и `Длительность` пустыми.
4. Проверить ASR, устройство, число спикеров.
5. Запустить выбранный файл.
6. Дождаться `done`.
7. Прослушать samples, назвать спикеров.
8. Открыть нужный экспорт.

### 2. Тестовый фрагмент

1. Выбрать запись.
2. Указать `Старт` и `Длительность`, например `0` и `30`.
3. Запустить выбранный файл.
4. Быстро проверить качество ASR/диаризации.
5. При необходимости изменить настройки и включить `Пересчитать`.

### 3. Пакетная обработка Inbox

1. Положить несколько файлов в `Inbox`.
2. Выбрать общий output folder.
3. Выставить общие настройки.
4. Поставить весь `Inbox` в очередь.
5. Сервер обрабатывает файлы последовательно, чтобы не перегружать локальный компьютер.
6. По мере готовности открывать результаты каждой задачи.

### 4. Разметка спикеров

1. Выбрать готовую задачу.
2. Прослушать sample каждого спикера.
3. Вписать имена.
4. Нажать `Применить имена`.
5. Сервис перерендерит exports без повторного ASR/diarization.

### 5. Повторная обработка

1. Выбрать файл и настройки.
2. Включить `Пересчитать`.
3. Запустить снова.
4. Новая задача перезапишет артефакты выбранного output folder.

### 6. Экспорт и проверка

1. После `done` открыть `Общий Markdown` для полной диагностики.
2. Открыть `Чистый + время`, если нужна редактура с таймкодами.
3. Открыть `Чистый` или `TXT`, если нужен финальный текст без технических деталей.

## Интерфейсная модель

- Левый столбец: `Inbox` и настройки запуска.
- Центральный столбец: локальная очередь задач и журнал.
- Правый столбец: проверка результата, samples, имена, exports.

Такой layout поддерживает все сценарии без перехода между страницами и без потери контекста.
