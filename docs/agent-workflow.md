# Agent Workflow

Дата: 2026-06-26.

Этот документ нужен для совместной работы нескольких AI-агентов над локальным проектом Voice Recognizer.

Главные entrypoints для агентов:

- `AGENTS.md` - общие правила для всех агентов;
- `CLAUDE.md` - короткая инструкция для Claude Code;
- `.agents/task-board.md` - текущие задачи, ownership и suggested prompts;
- `.agents/review-checklist.md` - приемка diff.

## Рабочие правила

- Не трогать аудио, `.env`, `.cache/`, `.models/`, `outputs/` и любые приватные документы без отдельного указания.
- Не откатывать чужие изменения.
- Перед изменением файла читать его актуальное содержимое.
- Держать изменения маленькими и проверяемыми.
- Для ручных правок использовать patch/edit инструменты, а не перезаписывать файлы целиком.
- После изменения кода запускать минимальную проверку: `python -m compileall src` или более точные тесты, если они есть.
- В финале всегда перечислять измененные файлы и что проверено.

## Git-модель

Текущий этап использует локальный git, без публикации наружу.

Рекомендуемая модель:

1. `main` хранит рабочий baseline.
2. Новые изменения делаются маленькими тематическими коммитами.
3. Для крупной независимой работы использовать ветку с префиксом `codex/`.
4. Перед коммитом проверять:
   - `git status --short`;
   - `git diff --cached`;
   - что нет `.env`, аудио, outputs, cache, моделей и временных файлов.

Коммит должен отвечать на вопрос: "какая пользовательская или инженерная способность стала лучше?"

## Роли агентов

### Main implementation agent

Отвечает за:

- архитектуру pipeline;
- backend/web integration;
- git baseline;
- приемку чужих предложений;
- финальную проверку пользовательских сценариев.

### UX/redesign agent

Пишет proposal, wireflow и acceptance criteria для интерфейса.

Write scope:

- `docs/agent-redesign-proposal.md`

Не меняет код, README и текущие сценарии без согласования.

### Review agent

Проверяет конкретный diff.

Фокус ревью:

- баги;
- регрессии;
- потеря приватности;
- конфликт локального и self-host сценария;
- неработающие команды запуска;
- edge cases длинных файлов и batch режима.

## Prompt для UX/redesign агента

```text
Ты второй AI-агент в проекте Voice Recognizer.

Контекст: это приватный local-first/self-host сервис для транскрибации длинных диктофонных записей. Требования: локально или на своем сервере, без подписок, обычные аудиофайлы с телефонов/диктофонов/петличек, выбор ASR/AI моделей включая сильные русские модели, batch mode, отсутствие лимита длины за счет chunking/resume, speaker diarization и экспорт в текстовые форматы.

Изучи README.md, docs/*.md и src/voice_recognizer/web.py.

Не меняй код. Создай docs/agent-redesign-proposal.md:
1. ключевые пользовательские сценарии;
2. рекомендуемая информационная архитектура;
3. конкретные улучшения текущего UI;
4. состояния ошибок, длинных задач и batch режима;
5. приемочные критерии для реализации редизайна.

Не трогай другие файлы, не откатывай чужие изменения.
```

## Prompt для review агента

```text
Ты review agent проекта Voice Recognizer.

Проверь текущий diff как code review. Не исправляй код сам, если не попросят. Начни с findings по серьезности, с точными файлами и строками. Особое внимание: приватность, попадание аудио/токенов в git, длинные файлы, batch режим, speaker labeling, запуск/остановка сервера, понятные ошибки для локального пользователя.

Если критичных проблем нет, так и скажи. В конце перечисли остаточные риски и какие проверки стоит запустить.
```

## Definition of Done для изменений

- Изменение соответствует одному из требований из `docs/product-requirements.md`.
- Приватные данные не попали в git.
- Пользовательский сценарий проходит от начала до результата или явно помечен как еще не реализованный.
- Ошибка не оставляет пользователя без следующего действия.
- Результаты можно открыть из UI или найти по documented path.
- Для кода выполнена минимальная проверка.
