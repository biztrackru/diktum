# UX Audit — локальный web UI

Дата: 2026-06-26.
Автор: Claude (UX/product track).
Объект: `app/src/voice_recognizer/web.py` (single-file web UI, ~1975 строк), фактическое состояние на ветке `codex/upload-files-queue`.

Метод: чтение реального кода UI (HTML/CSS/JS внутри `web.py`) и payload-функций, сверка с `docs/agent-redesign-proposal.md`, `docs/user-scenarios.md`, `.agents/review-checklist.md` и WCAG 2.1 AA. Это аудит интерфейса, не аудит pipeline. Я не редактирую `web.py` — нахождения передаются implementation-агенту через `.agents/handoff-ux-redesign.md`. Цель к каждой находке: `severity / file:line / risk / fix`.

## Краткий вердикт

Текущий UI — крепкая основа: правильная трёхзонная раскладка (Inbox/настройки → очередь/журнал → результат), сегментированные переключатели режима и спикеров, диапазон/точное число спикеров, корректный upload, range-запросы для samples (`web.py:1377`), privacy-индикатор `127.0.0.1` (`web.py:762`). Он уже частично реализует `agent-redesign-proposal.md`.

Главный разрыв не визуальный, а операторский: интерфейс ведёт себя как обёртка над CLI, а не как панель управления длинной обработкой. Три вещи бьют по основному пользователю сильнее всего:

1. для часовых файлов не видно ни этапа, ни elapsed, ни «жив ли процесс» (F3);
2. ошибки заканчиваются тупиком без понятного действия (F4);
3. ввод имён спикеров может стираться 2-секундным polling'ом (F2) — это прямо нарушает `review-checklist.md`;
4. результаты не переживают рестарт и не видны из Inbox: обработал вечером — утром в UI пусто, хотя файлы лежат в `outputs/` (F15, F16).

Плюс одна сквозная доступность: фокус с клавиатуры невидим на всех основных контролах (F1).

Примечание: ссылки `file:line` привязаны к состоянию `web.py` на ветке `codex/upload-files-queue` на дату аудита; при правках файла строки сдвинутся.

## Что уже хорошо (не трогать)

Трёхзонная раскладка и responsive-сворачивание (`web.py:346-352`, `714-747`); сегментные контролы режима и спикеров с disabled-логикой полей (`963-983`); range-запросы для аудио-samples (`1377-1399`); жёсткое ограничение output внутри `outputs/` (`1368-1371`); privacy-индикатор `127.0.0.1`; экранирование HTML/атрибутов (`1343-1353`). Редизайн должен сохранить эту основу.

## Приоритезация и оценка объёма

Размер: S — точечная правка в `web.py`; M — заметный блок UI + 1–2 эндпоинта; L — затрагивает формат данных/манифест и pipeline.

| Очередь | Находки | Почему | Размер |
|---------|---------|--------|--------|
| 1. Операторская связка | F1, F2 | клавиатура + неломкий ввод имён; закрывает review-checklist и WCAG-фокус | S, S |
| 2. Длинные задачи | F3, F4 | этапы/elapsed и диагностируемые ошибки — основной путь часовых файлов | M, M |
| 3. Результаты на диске | F15, F16 | «оставил на ночь — вернулся»: библиотека `outputs/` + бейдж «обработан» (твоя идея) | M (+S обогащение манифеста) |
| 4. Повседневная ясность | F5, F6, F7, F8 | локализация, тест-фрагмент, метаданные Inbox, группировка экспорта | S, M, M, S |
| 5. Устойчивость/доступность | F9, F10 | без churn'а очереди, объявления для AT | M, S |
| 6. Полировка | F11, F12, F13, F14 | чекбоксы пакета, живой стэпер, контраст, переходы | S каждый |

Целевое поведение каждой находки показано в прототипе `docs/ux/voice-recognizer-prototype.html`, а проверяемые критерии приёмки — в `docs/ux-acceptance-scenarios.md`. Реализацию в `web.py` ведёт implementation-агент (см. `.agents/handoff-ux-redesign.md`).
