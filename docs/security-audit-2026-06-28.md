## 1. Резюме

Проект в хорошем состоянии для своего этапа. Базовые вещи, на которых обычно горят локальные веб-приложения, здесь сделаны правильно: **нет `shell=True` и инъекций команд, аккуратно закрыт path traversal, экранирование на фронте, install-пак не тащит секреты, бинарь и часть моделей качаются по HTTPS с проверкой SHA-256, `.env` не в гите.**

Перед публикацией нужно закрыть один **High** (защита локального сервера от DNS-rebinding / CSRF — критично именно для «приватного» продукта) и несколько **Medium** (лимиты на загрузку, deprecated `cgi`, пины зависимостей, проверка целостности основных моделей). Остальное — Low и гигиена репозитория.

**Вердикт:** публиковать можно после закрытия High + Medium-1..2 и чистки репозитория. Полный план — в разделе 7.

## 2. Что сделано хорошо (не сломать при правках)

Это важно зафиксировать, чтобы рефакторинг не убрал существующую защиту.

- **Нет инъекций команд.** Везде `subprocess` вызывается со списком аргументов, без `shell=True` (`web.py:3603`, `3941`, `4001`; `audio.py:68,100`; `gigastt.py:121`). Имена файлов и имена спикеров уходят как отдельные argv-элементы — даже спецсимволы шелла безопасны.
- **Path traversal закрыт правильно** — везде паттерн «resolve(), затем relative_to()»: выдача файлов `_serve_output` (`web.py:3411-3418`), приём загрузок `_unique_inbox_path` + `_safe_upload_name` (`web.py:4196-4233`), `_resolve_output_dir` (`4342-4352`), `_resolve_source` (только имена из Inbox, `4134-4138`), источники из манифеста (`4117-4131`).
- **Загрузки санируются:** имя приводится к basename, белый список расширений, контроль контейнера каталогом.
- **XSS на фронте контролируется:** пользовательские данные идут через `escapeHtml`/`escapeAttribute`, лог рендерится через `textContent` (`web.py:2233-2247`).
- **Install-пак безопасен:** `build_install_pack.sh` копирует по белому списку; проверено — в собранном паке **нет** `.env`, токенов, `.git`, аудио, `.venv`, моделей. `.env` создаётся на целевой машине с `chmod 600`.
- **Цепочка поставки бинаря:** GigaSTT (GitHub Releases) и RUPunct (HF) качаются по HTTPS с **пиннингом SHA-256** (`setup_gigastt.sh`).
- **Секретов нет в гите:** `.env` никогда не коммитился, в истории и в трекнутых файлах токенов не найдено.
- **Приватность по существу выполняется:** аудио и транскрипты не покидают машину; ASR — локальный бинарь на локальных моделях.
- **Длинные файлы:** ASR разбивается на чанки с кэшем/возобновлением (`cli.py:259+`), что снижает риск падений на больших записях.

## 3. Детальные находки

### H-1 (High) — Локальный сервер не проверяет `Host`/`Origin`: DNS-rebinding и CSRF

**Где:** `app/src/voice_recognizer/web.py`, класс `VoiceRecognizerHandler` (`do_GET`/`_handle_get_or_head` ~`106-143`, `do_POST` ~`145-240`, `do_DELETE` ~`242-253`). Проверки заголовка `Host` или `Origin` нет нигде.

**Риск.** Сервер слушает только localhost, но это **не** защищает от браузерных атак, пока на машине открыт браузер:

1. **DNS-rebinding → кража транскриптов (главный риск для «приватного» продукта).** Пока сервер запущен, пользователь заходит на вредоносный сайт. Сайт через DNS-rebinding заставляет браузер считать свой домен указывающим на `127.0.0.1:8765`, обходит same-origin и читает `GET /api/results`, `/api/inbox`, `/outputs/<любой результат>` — то есть **выкачивает чужие записи и расшифровки наружу**. Для продукта, чья суть — приватность, это критично.
2. **CSRF (побочные действия).** Чужая вкладка может слать POST/DELETE на `127.0.0.1:8765` и создавать/удалять задачи, чистить результаты, забивать Inbox (детали — в M-1).

**Почему High при localhost-only:** вся ценность продукта — конфиденциальность, а здесь возможна тихая экзфильтрация расшифровок; эксплойт реалистичный (нужен лишь открытый браузер и заход на «плохой» сайт), а фикс — дешёвый.

**Фикс (рекомендуется все три уровня):**
- **Allowlist `Host`** для каждого запроса: разрешать только `127.0.0.1:<port>` и `localhost:<port>`, иначе `403`. Это закрывает DNS-rebinding.
- **Проверка `Origin`/`Sec-Fetch-Site`** для изменяющих методов (POST/DELETE): если `Origin` присутствует и не localhost — `403`. Это закрывает CSRF (где `Host` остаётся валидным).
- Опционально — генерировать при старте случайный токен сессии и зашивать его в выдаваемую страницу; API требует его в заголовке. Это «ремень и подтяжки», но для single-user может быть избыточно.

### M-1 (Medium) — JSON-эндпоинты не проверяют `Content-Type` → CSRF «простым запросом»

**Где:** `web.py:3448-3454` (`_read_json_body` читает тело и `json.loads` независимо от типа); `do_POST` для `/api/jobs` (`207-240`), `/cancel`, `/speaker-names`, `/rerun`.

**Риск.** Кросс-доменный `fetch` с `Content-Type: text/plain` — это «простой запрос», браузер **не** делает preflight. Поскольку обработчик игнорирует тип содержимого, такой запрос пройдёт и создаст/изменит задачу (CSRF без preflight). `/api/uploads` отдельно разрешает `multipart/form-data` (`web.py:3458`) — тоже «простой» тип, значит загрузку в Inbox можно инициировать кросс-доменно.

**Фикс:** для изменяющих JSON-эндпоинтов требовать строго `Content-Type: application/json` (иначе `415`). Это вынуждает браузер на preflight, который без CORS-заголовков сервера провалится → CSRF блокируется. Вместе с проверкой `Origin` из H-1 закрывает класс полностью.

---

### M-2 (Medium) — Нет лимитов на размер загрузки и тела запроса → локальный DoS

**Где:** `_save_uploads` (`web.py:3456-3486`) — `cgi.FieldStorage` без ограничения; `_read_json_body` (`web.py:3449-3451`) — читает весь `Content-Length` в память.

**Риск.** Запрос с огромным телом или загрузка гигантских файлов исчерпывают память/диск. Само по себе — localhost, но в связке с CSRF-загрузкой (M-1) внешняя страница может незаметно забить диск пользователя.

**Фикс:** ввести максимум на тело (`Content-Length` → `413` при превышении), максимум на размер одного файла и суммарный размер загрузки, проверять свободное место перед записью. Значения сделать конфигурируемыми.

---

### M-3 (Medium) — `cgi` устарел и удалён в Python 3.13

**Где:** `web.py:3` (`import cgi`), `web.py:3460` (`cgi.FieldStorage`). В `pyproject.toml` стоит `requires-python = ">=3.10,<3.13"` — фактически потолок версии стоит именно из-за этого.

**Риск.** На Python 3.13+ модуль отсутствует → приложение не запустится. Потолок `<3.13` мешает пользователям с новым Python и будет всё чаще ломать установку.

**Фикс:** заменить разбор multipart на свой минимальный парсер или на поддерживаемую библиотеку (например `multipart`/`python-multipart`), затем снять потолок версии Python. Это также повод добавить лимиты из M-2.

---

### M-4 (Medium) — Незапиненные зависимости и git-зависимость без коммита

**Где:** `app/pyproject.toml`.

**Риск.** Диапазоны `>=` без верхней границы (`typer`, `rich`, `numpy`, `pyannote.audio`) дают невоспроизводимые сборки: будущий релиз может что-то сломать или внести вредонос. Особо опасно `gigaam @ git+https://github.com/salute-developers/GigaAM.git` — без `@<commit/tag>` ставится то, что в этот момент в ветке по умолчанию; компрометация репозитория = выполнение чужого кода у пользователей.
*Смягчение:* `setup_local_mac.sh` ставит `.[diarization]`, а не `.[asr]`, поэтому git-зависимость по умолчанию **не** тянется — но это мина для всех, кто поставит `.[asr]`.

**Фикс:** запинить `gigaam` к конкретному коммиту/тегу; добавить разумные верхние границы основным пакетам; зафиксировать полный набор через lock-файл (`pip-tools`/`uv`) и поставлять его. Это сильно повышает воспроизводимость для сторонних пользователей.

---

### M-5 (Medium) — Основные модели GigaAM v3 без независимой проверки целостности

**Где:** `setup_gigastt.sh` — строка вида `"${BIN_DIR}/gigastt" download --model-dir … --prequantized`. Бинарь и RUPunct пиннятся по SHA-256, а основные ONNX-модели (encoder/decoder/joint) скачивает сам бинарь без независимой проверки в скрипте.

**Риск.** Целостность главного ASR-актива зависит от внутренней логики стороннего бинаря. Если у источника моделей подменят файл, скрипт это не заметит.

**Фикс:** после загрузки проверять SHA-256 ключевых файлов модели по списку ожидаемых хэшей (как уже сделано для RUPunct в том же скрипте). Где невозможно — задокументировать, что целостность обеспечивает бинарь.

### L-1 (Low) — Битый git-ref

**Где:** `git fsck` → `error: refs/heads/_t/x: invalid sha1 pointer 0000…0000`.

**Риск.** Повреждённая ссылка ломает часть git-операций и может «уехать» при публикации.

**Фикс:** удалить битый ref (`git update-ref -d refs/heads/_t/x` или удалить файл в `.git/refs/heads/_t/x` и запись в `packed-refs`), затем `git fsck` начисто. Перед публикацией — собрать чистый репозиторий/`git gc`.

---

### L-2 (Low) — Раскрытие stdout подпроцесса в ответе об ошибке

**Где:** `web.py:4010` — `raise ValueError(f"... {process.stdout[-2000:]}")`, текст уходит клиенту как `{"error": …}`.

**Риск.** Локальные пути и детали окружения утекают в ответ HTTP. На localhost некритично, но в связке с H-1 — лишняя информация атакующему.

**Фикс:** клиенту — обобщённое сообщение; полный stdout писать только в локальный лог/журнал задачи.

---

### L-3 (Low) — Чтение файла целиком в память при выдаче `/outputs/`

**Где:** `web.py:3432` — `self.wfile.write(target.read_bytes())` для не-range GET.

**Риск.** Пик памяти на больших выгрузках (длинные WAV-сэмплы, крупные результаты).

**Фикс:** отдавать потоково кусками (range-ветка уже читает порциями — переиспользовать подход).

---

### L-4 (Low) — Реклама нереализованного LM Studio в `.env.example`

**Где:** `app/.env.example:8-9` (`LM_STUDIO_BASE_URL`, `LM_STUDIO_MODEL`). В коде использования нет (проверено).

**Риск.** Мёртвая/вводящая в заблуждение настройка. Если позже подключить пост-обработку, `base_url` сможет указывать на удалённый сервер — тогда транскрипты уйдут с машины. Это прямой конфликт с обещанием приватности.

**Фикс:** убрать из примера до реализации; при реализации — ограничить `base_url` локальным хостом и явно предупреждать в UI, если он не локальный.

---

### L-5 (Low) — `VOICE_RECOGNIZER_HOST` позволяет открыть сервер в сеть без аутентификации

**Где:** `app/scripts/start_server.sh` — `HOST="${VOICE_RECOGNIZER_HOST:-127.0.0.1}"`.

**Риск.** Дефолт безопасный, но если пользователь захочет «открыть на телефоне» и поставит `0.0.0.0`, сервер без аутентификации станет доступен всей сети.

**Фикс:** при `host`, отличном от `127.0.0.1/localhost`, печатать явное предупреждение и (после фикса H-1) требовать осознанного подтверждения; в доке прямо отметить, что сетевой доступ не предусмотрен.

---

### L-6 (Low) — Раздача учит снимать quarantine (нет подписи/нотаризации)

**Где:** `unblock_macos.sh`, `START_HERE.txt` (инструкция `xattr -dr com.apple.quarantine`).

**Риск.** Пользователей приучают снимать защиту Gatekeeper с скачанного — ровно то, чем пользуются распространители вредоносного ПО. Документировано аккуратно, но риск присущ модели.

**Фикс (стратегический):** для широкой раздачи — Apple Developer ID signing + notarization установочного пакета. Это снимает предупреждения штатно и убирает необходимость учить обходу Gatekeeper.

### I-1 / I-2 (Info)

- **I-1:** Homebrew ставится официальным `curl … | bash` от HEAD (`setup_local_mac.sh:226`) — индустриальный стандарт, но не запинено и может запрашивать пароль администратора. Для нетехнических пользователей стоит предупредить, что это официальный установщик Homebrew и зачем нужен пароль.
- **I-2:** Корень доверия для ASR — аккаунт одного человека (`github.com/ekhodzitsky`, `huggingface.co/ekhodzitsky`). Пиннинг SHA-256 защищает от подмены конкретного релиза, но провенанс стоит явно задокументировать в README.

## 4. Приватность (отдельно, т.к. это суть продукта)

**Главное обещание выполняется:** аудио и тексты не покидают машину. ASR — локальный бинарь на локальных моделях; pyannote после первичной загрузки работает локально; токен HF не логируется (`diarization.py:36-42, 76`).

**Сетевые касания, которые надо честно описать в README** (чтобы заявление о приватности было корректным):
1. **Первый запуск диаризации** скачивает модель pyannote с huggingface.co под токеном пользователя (уходит только запрос модели, не аудио).
2. **Установка** тянет Homebrew/ffmpeg/Python-пакеты и модели из интернета.
3. После установки обработка — офлайн.

Рекомендация: добавить в README раздел «Что и когда уходит в сеть» — это усилит, а не ослабит доверие.

## 5. Стабильность

- **Длинные файлы:** ASR-чанкинг с кэшем и возобновлением (`cli.py:259+`) — хорошо. Диаризация грузит весь WAV в память (`diarization.py:_load_wav_as_tensor`) — для очень длинных записей возможен пик памяти; стоит проверить на 2–3 часах и при необходимости резать.
- **Конкурентность:** один рабочий поток на очередь, глобальный `JOBS_LOCK` — для single-user адекватно.
- **Совместимость Python:** см. M-3 (потолок `<3.13`).
- **Обработка ошибок:** статусы задач (`failed/canceled`) и коды возврата проброшены аккуратно.

## 6. Рекомендация по способу публикации (вы пока не выбрали)

**Рекомендуемый путь — гибрид, в два темпа:**

1. **Сначала — публичный GitHub с исходниками** (после фикса H-1, M-1, M-2 и чистки репозитория). Открытый код = аудируемость; install-пак уже не содержит секретов. Добавить: `LICENSE`, `SECURITY.md` (куда сообщать об уязвимостях), раздел приватности (раздел 4), запиненные зависимости (M-4).
2. **Готовый install-пак — как release-asset для нетехнических людей.** Сейчас он не подписан, поэтому до широкой раздачи честно предупреждать про Gatekeeper, а в идеале — вложиться в Developer ID + нотаризацию (L-6).

Чего избегать на старте: раздавать install-пак широкой аудитории без подписи и без фикса H-1 — это худшая комбинация (учим обходить Gatekeeper + сервер уязвим к rebinding).

## 7. План действий (по приоритету)

**Блокеры публикации**
1. H-1 — добавить allowlist `Host` + проверку `Origin`/`Sec-Fetch-Site`.
2. M-1 — требовать `application/json` на изменяющих эндпоинтах.
3. M-2 — лимиты размера тела/загрузки.
4. L-1 — починить git-ref, собрать чистый репозиторий.
5. Гигиена публичного репо: `LICENSE`, `SECURITY.md`, раздел приватности, проверка, что `.gitignore` покрывает всё приватное (уже покрывает: `.env*`, `Inbox/`, `outputs/`, `.models/`, `tools/bin/`, аудио).

**До широкой раздачи**
6. M-4 — запинить зависимости (особенно `gigaam`), добавить lock-файл.
7. M-5 — проверка SHA-256 основных моделей.
8. M-3 — уйти от `cgi`, снять потолок Python.
9. L-4 — убрать неработающий LM Studio из `.env.example`.
