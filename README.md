# Диктум

**Диктум** - локальный инструмент для macOS, который превращает длинные русскоязычные аудиозаписи в рабочие текстовые протоколы: с пунктуацией, таймкодами, разделением по спикерам и экспортом в Markdown/TXT.

Проект создается для интервью, обучений, вебинаров, консультаций, семинаров и больших диктофонных архивов, где нужен не просто сырой текст, а материал, с которым можно дальше работать человеку или AI-агенту.

## Что умеет

- Распознает русскую речь локально через `GigaSTT / GigaAM v3 RNNT`, локальный `GigaAM v3 e2e CTC` или дополнительный `GigaAM v3 e2e RNNT`.
- Разделяет запись по спикерам через pyannote.
- Обрабатывает длинные файлы чанками, без практического лимита в 1-2 часа.
- Поддерживает пакетную обработку папки `Inbox/`.
- Позволяет прослушать samples спикеров и назначить имена после обработки.
- Сохраняет результаты локально в `outputs/`.
- Экспортирует raw, clean и edited варианты в Markdown/TXT.
- Запускается как локальный web UI в браузере через double-click `.command` launchers.

## Приватность

Диктум спроектирован как local-first инструмент:

- аудио остается в `Inbox/`;
- результаты остаются в `outputs/`;
- токены лежат только в локальном `.env`;
- web UI слушает `127.0.0.1` и не предназначен для доступа из сети;
- обработка аудио не отправляет записи во внешние ASR-сервисы.

Сеть нужна при установке и первом запуске моделей:

- Homebrew/ffmpeg/Python dependencies;
- GigaSTT binary and models;
- pyannote model download through your Hugging Face token.

## Требования

Рекомендуется:

- macOS 14 или новее на Apple Silicon;
- 16 GB RAM минимум;
- 32 GB RAM комфортнее для длинных записей и batch;
- 20-30 GB свободного места для моделей, cache и результатов;
- интернет при первой настройке;
- Hugging Face token с доступом к `pyannote/speaker-diarization-community-1`, если нужно разделение по спикерам.

Ориентир по установочному трафику: несколько GB, зависит от уже установленных Homebrew/Python/модельных компонентов.

## Быстрый старт

### Через trial pack

Если у вас есть zip-сборка:

1. Распакуйте архив в обычную папку.
2. Откройте `START_HERE.txt`.
3. При необходимости запустите `Разблокировать Диктум.command`.
4. Запустите `Настроить Диктум.command`.
5. Запустите `Проверить Диктум.command`.
6. Запустите `Запустить Диктум.command`.
7. Откройте локальный интерфейс на `http://127.0.0.1:8765/`.

### Из исходников

```bash
git clone https://github.com/biztrackru/diktum.git dictum
cd dictum
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r app/requirements-macos-arm64-py312.lock
.venv/bin/python -m pip install --no-deps --no-build-isolation -e app
cp app/.env.example .env
```

Добавьте в `.env` read-only Hugging Face token:

```bash
HF_TOKEN=hf_your_token_here
```

Подготовьте GigaSTT/GigaAM:

```bash
app/scripts/setup_gigastt.sh
```

Запустите локальный web UI:

```bash
.venv/bin/dictum web --port 8765
```

Старый CLI-алиас `voice-recognizer` сохранен для совместимости:

```bash
.venv/bin/voice-recognizer web --port 8765
```

## Как пользоваться

1. Положите `.m4a`, `.mp3`, `.wav` или `.mp4` в `Inbox/` либо загрузите файл через web UI.
2. Выберите файл и параметры обработки.
3. Запустите обработку.
4. Дождитесь статуса `done`.
5. Прослушайте samples спикеров и задайте имена.
6. Откройте Markdown/TXT результат из интерфейса.

CLI-пример:

```bash
.venv/bin/dictum process 'Inbox/recording.m4a' --asr-engine gigastt-gigaam-v3
```

Batch-пример:

```bash
.venv/bin/dictum batch-process Inbox --output-dir outputs/pipeline-batch
```

## Сборка дистрибутива

```bash
app/scripts/build_install_pack.sh
```

Скрипт создает `.dist/Диктум Trial <timestamp>.zip` и кладет туда только пользовательскую поверхность:

- root launchers;
- `START_HERE.txt`;
- `VERSION.txt`;
- `FEEDBACK_TEMPLATE.txt`;
- `app/`;
- пустые `Inbox/` и `outputs/`.

В архив намеренно не попадают `.env`, `.venv`, `.models`, `.cache`, `logs`, `tools/bin`, приватные аудио, outputs, internal/agent files, tests, docs and developer-only scripts.

## Конфигурация

### Локальные модели и обновления

Обычная настройка устанавливает GigaSTT 2.22.0, проверенный набор GigaAM RNNT,
GigaAM e2e CTC и Silero v4/v6. Все ресурсы скачиваются только на этапе настройки,
проверяются по SHA-256 из `app/config/resources.json` и хранятся в `.models/`.
Повторная настройка проверяет версии и содержимое, а заменяемые файлы сохраняет
в `.cache/resource-backups/`. Аудио, результаты и профили голосов не изменяются.

CTC доступен без установленного Handy:

```bash
.venv/bin/dictum process 'Inbox/recording.m4a' --asr-engine handy-gigaam-v3-e2e-ctc
```

Он предпочитает `.models/ctc/model.int8.onnx`, `.models/ctc/vocab.txt` и
`.models/vad/silero_vad_v4.onnx`. Для совместимости сохраняется fallback на файлы
Handy и Silero v4, если собственные ресурсы ещё не установлены. Обработка CTC
не скачивает модели. Телеметрия pyannote и Hugging Face отключена для CLI и web.

Silero v4 остаётся по умолчанию: на коротком сравнении v6 меняет границы окон
и текст, но не даёт подтверждённого улучшения. Для явной проверки v6 задайте
`VOICE_RECOGNIZER_CTC_VAD_PATH=.models/vad/silero_vad_v6.onnx` в локальном `.env`
для web jobs или в окружении CLI. Новые CTC-результаты пересчитываются при смене
файла VAD или версии ONNX Runtime.

Дополнительную модель со встроенной пунктуацией можно установить и выбрать отдельно:

```bash
PYTHONPATH=app/src .venv/bin/python -m voice_recognizer.assets install e2e-rnnt
.venv/bin/dictum process 'Inbox/recording.m4a' --asr-engine e2e-rnnt
```

Этот профиль хранится в `.models/gigastt-e2e/`, создаёт результаты с отдельным
суффиксом `.gigaam-e2e-rnnt` и не меняет выбор ASR по умолчанию. GigaSTT запускается
в offline-режиме: при отсутствии ресурса нужно повторить настройку.

Для подготовки без сети из уже загруженного кеша:

```bash
PYTHONPATH=app/src .venv/bin/python -m voice_recognizer.assets install --offline
```

Сборка рассчитана на Python 3.12 и macOS 14+ arm64. Lock содержит точные версии
и хеши транзитивных зависимостей; для его пересоздания используйте uv с
`MACOSX_DEPLOYMENT_TARGET=14.0` и extras `ctc`, `diarization`, `docs`, `installer`.

Для самостоятельного размещения тех же файлов задайте `VOICE_RECOGNIZER_CTC_MODEL_DIR` и `VOICE_RECOGNIZER_CTC_VAD_PATH` в окружении процесса. Для web jobs их также можно задать в локальном `.env`.

В web UI модель выбирается в списке ASR. Локальный выбор по умолчанию для UI и CLI `process`/`batch-process --asr-engine auto` можно сохранить в `.cache/asr-engine.json`:

```json
{"engine": "handy-gigaam-v3-e2e-ctc"}
```

Без этого файла остаётся RNNT. Чтобы вернуть прежний default, запишите `{"engine":"gigastt-gigaam-v3"}`. После изменения перезагрузите страницу интерфейса.

CTC обрабатывает запись короткими окнами до 22 секунд; Silero помогает выбирать границы, перекрывающийся контекст защищает стыки. Слова получают приблизительные CTC-таймкоды с шагом 40 мс для существующего разделения по спикерам. RNNT hotwords к CTC не применяются. Новые файлы содержат суффикс `.gigaam-e2e-ctc`, поэтому прежние RNNT-результаты не перезаписываются. Имена спикеров можно переносить между записями через локальные профили голосов с подтверждением предложений.

Это воспроизведение конкретного пути Handy для проверки в реальном использовании, а не обещание превосходства на любых записях. Ошибки на шуме и перекрывающихся голосах остаются возможны.

`app/config/speaker-counts.json` можно использовать для локальных подсказок по числу спикеров для конкретных файлов. В публичной версии файл пустой.

Для ASR hotwords создайте локальный файл:

```bash
cp app/config/hotwords.example.txt app/config/hotwords.txt
```

`app/config/hotwords.txt` игнорируется Git и не должен попадать в публичные коммиты.

## Ограничения

- Основной установочный ASR backend — `gigastt-gigaam-v3`; опциональный CTC требует локальных файлов модели и зависимостей `app[ctc]`.
- Диаризация зависит от pyannote и Hugging Face model access.
- Качество разделения спикеров может снижаться на перекрывающихся голосах и шумных записях.
- macOS signing/notarization пока не настроены.
- Self-host/Docker profile и native macOS wrapper находятся в roadmap, но не в текущем alpha baseline.

## Локальные профили голосов

В готовом результате откройте вкладку **Спикеры**. Чтобы сохранить голос, введите имя, нажмите **Применить имена**, затем **Запомнить голос** у этого спикера. Повторное сохранение того же имени из другой записи добавляет пример в существующий профиль.

При обработке новых файлов Диктум автоматически готовит предложения имён. Для уже обработанных файлов нажмите **Узнать голоса**. Отметьте нужные совпадения и нажмите **Подтвердить выбранные имена**: имена появятся в Markdown и остальных текстовых результатах. Подтверждение предложения само по себе не добавляет образец в профиль. Неуверенные совпадения остаются без имени; ранее применённые имена сохраняются.

В разделе **Профили голосов** можно забыть профиль. Это не удаляет имена из готовых текстов. Банк хранится в `.voice-profiles/profiles.json` отдельно от временного кэша; сохраняйте эту папку при переносе локальной установки. В Git она не включается. Аудио и голосовые признаки не отправляются во внешние сервисы. Для сравнения используется локальный embedding checkpoint уже установленной модели `pyannote/speaker-diarization-community-1`; при его отсутствии интерфейс сообщает об ошибке, а транскрибация остаётся доступной.

Профили предлагают знакомые голоса между файлами. Общая нумерация всех участников многосоставного мероприятия пока не поддерживается. Короткая речь, одновременные реплики и другой микрофон могут мешать совпадению: дополнительные подтверждённые примеры с разных устройств помогают расширять профиль.


## Выбор источников и папка результатов

В **Источниках** файлы по умолчанию расположены по дате изменения: новые сверху. Можно выбрать обратный порядок или сортировку по имени; выбор сохраняется в браузере.

Для пакета выберите режим **Несколько файлов**, отметьте нужные записи в источниках и нажмите **Обработать выбранные**. Изначально ничего не отмечено; новые файлы в папке не включаются в выбор автоматически. Сортировка сохраняет отметки. Кнопки **Все** и **Ни одного** управляют выбором явно.

Во вкладке **Спикеры** образец голоса, предложение профиля и поле имени находятся рядом. Счётчик показывает число подписанных спикеров, а фильтр **Без имени** помогает сосредоточиться на оставшихся. Введённые имена сохраняются командой **Применить имена**.

У готового результата над вкладками есть **Перейти в папку**: на macOS она открывает Finder в каталоге, где лежат файлы результата.
