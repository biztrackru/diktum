## Risks

- `.agents/task-board.md` — общий файл; Codex тоже пишет в него («minimal README/task-board updates»). Я редактировал только блок `### Claude Code`; при параллельной правке мерджить аккуратно по разделам.
- Прототип тянет шрифты IBM Plex с CDN ради дизайна. Для local-first продукта в продакшене шрифты надо self-host'ить или принять системный fallback (заложен в стек) — отмечено в шапке файла.
- F2 в текущем `web.py` частично прикрыт guard'ом по render-key, но рвётся при `force:true`/смене ключа. Эталонный фикс (controlled-инпуты + сохранение фокуса/каретки) реализован в прототипе — переносить именно его.
- Манифест сейчас не хранит `start`/`duration`/`asr_engine`/`device`. Базовая библиотека результатов (F15/F16) работает и без этого (наличие манифеста = «готово», `source` уже есть). Но переименование спикеров **для тест-фрагмента из библиотеки** без этих полей реджойнит полный файл — поэтому для полной поддержки нужно мягкое обогащение манифеста (см. Data contract).
- Скан `outputs/**/*.manifest.json` для библиотеки результатов нужно кэшировать (инвалидация по mtime каталога / при завершении задачи), иначе на каждом запросе будет лишний обход диска.

## Самооценка: слабые места и осознанные упрощения

Честно, чтобы было что критиковать дальше:

- **Прототип — мок, есть риск дрифта от реального API.** Снижено разделом «Data contract» (поля прототипа ↔ поля backend), но при реализации сверять контракт, а не пиксели.
- **F15/F16 в v1 были недооценены.** Изначально это шло одной строкой внутри F7; владелец справедливо вытащил это в отдельное направление. Теперь это F15/F16 + S10 + вид «Готовые».
- **Изменённый после обработки файл** (та же запись перезаписана) — детектится только при обогащении манифеста `source_size`/`source_mtime`; пометил как «желательное», не блокер.
- **Над-инженерия в прототипе:** псевдо-волна сэмпла и анимация «потока» в активном этапе — декоративны и при переносе в `web.py` не нужны; перенос — только паттерны (этапы, controlled-инпуты, focus-visible, группировка), не визуальный мусор.
- **Объём.** 16 находок + 10 сценариев — это бэклог на несколько итераций, а не один PR. Дробить по приоритету из аудита; не пытаться внедрить всё сразу.
- **Не покрыто:** удаление файлов/результатов из UI (housekeeping локального инструмента), пустые состояния первого запуска проработаны легко, поведение при частично готовых чанках — после появления чанкинга.

## Data contract (для результатов и Inbox-бейджа)

Минимум для F15/F16 — без изменения pipeline:

- **Результаты с диска:** новый `GET /api/results` → скан `outputs/**/*.manifest.json`, на каждый: `id` (синтетический, например хэш пути), `source` (basename из манифеста, `cli.py:479`), `output_dir`, `kind` (full/clip — из суффикса имени манифеста, `_clip_suffix`), `status` (`done`; `partial` если часть выходных файлов отсутствует), `completed_at` (mtime манифеста), плюс уже доступные `files`/`speaker_samples`/`speaker_names` через существующие `_manifest_files`/`_manifest_samples`.
- **Inbox payload** (`_inbox_file_payload`, `web.py:1708`) дополнить: `duration` (ffprobe, кэш), `processed` (bool), `results` (список совпадений по basename `source`).
- **Открытие результата из манифеста:** обобщить `_job_payload` → `_result_payload(manifest_path)`, чтобы результат рисовался без живого `Job`.
- **Переименование из библиотеки:** вариант `_apply_speaker_names`, восстанавливающий `source_path`/`output_dir` из манифеста.

Желательное обогащение `_write_manifest` (`cli.py:463-492`), чтобы закрыть edge-кейсы: `start`, `duration`, `asr_engine`, `device`, `created_at`, `completed_at`, `status`, `source_size`, `source_mtime`. Это делает rename-фрагмента из библиотеки точным и даёт детект «запись изменилась».

Новых внешних вызовов нет — только локальный `outputs/`. Приватность не меняется.
